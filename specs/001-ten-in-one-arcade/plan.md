# 實作計畫：霓虹十合一小遊戲廳

## 1. 方案摘要

採用零依賴的靜態單頁架構：`index.html` 提供語意化骨架，`styles.css` 負責視覺系統與響應式版面，`app.js` 負責大廳、共用遊戲面板、十款遊戲狀態與本機最佳分數，`src/rules.mjs` 放置可獨立測試的純規則函式。這能在 GitHub Pages、一般靜態伺服器或 Sites 的靜態輸出中直接執行。

視覺主題為「夜色中的遊戲廳」：深藍黑背景承托珊瑚橘、薄荷綠與電光藍，卡片採低對比邊框與微光，遊戲面板以大字狀態與明確操作區維持乾淨密度。

### 1.1 為何採用「霓虹遊戲廳」

十款小遊戲需要一個能快速傳達「現在就能玩」的共同入口；霓虹遊戲廳把街機的即時感、短回合與一點點競賽感濃縮成一致的視覺語言。深色底讓十張卡片保持整潔並降低視覺噪音，珊瑚橘、薄荷綠與電光藍則分別用於挑戰、成功與互動焦點，讓玩家不用閱讀太多就能找到下一步。這個方向也可用純 CSS、原生控件與少量 Canvas 完成，不需要外部圖片或品牌資產，適合快速載入與靜態部署。

## 2. 技術決策

### 2.1 不引入框架與第三方資產

十款遊戲的主要操作以按鈕、CSS 格子與一個小型 canvas 完成。這避免依賴套件、外部網路或圖片授權，也讓公開 repository 易於檢閱與部署。

### 2.2 共用遊戲面板

大廳卡片只負責選擇遊戲；開啟後由 `GameRuntime` 依遊戲 ID 建立面板 DOM、注入事件並在關閉或換遊戲時清理計時器。所有遊戲使用同一個結束區與重玩入口，降低認知負擔。

### 2.3 遊戲內輸入

- DOM 格子、按鈕與輸入框使用原生事件，並以 `data-action` 統一入口。
- 貪食蛇與完美堆疊使用 Canvas 做幾何繪製，但旁邊同步顯示文字狀態與按鈕控制。
- 方向鍵、WASD、Enter、Space 與 pointer 事件皆經過遊戲當前狀態判斷，避免背景遊戲繼續吃鍵盤事件。

### 2.4 本機資料

使用一個版本化的 `arcade-10-best-scores` JSON 物件儲存各遊戲最佳分數、已完成局數與上次遊玩時間。讀寫包在 `try/catch` 中；不可用時退回記憶體狀態。

### 2.5 互動與狀態修正

- 原生 `<button>` 統一監聽 `click`，讓滑鼠、觸控及鍵盤 Enter／Space 共用瀏覽器既有的啟用語意；`pointer` 只保留給日後需要座標或按壓狀態的非按鈕操作。
- 將方向反轉、蛇身碰撞與玩家統計正規化拆成 `src/rules.mjs` 純函式，直接測試快速連續輸入、尾端離開與異常儲存資料。
- 井字對決加入電腦回合鎖定狀態，重新渲染時停用所有空格，直到電腦完成落子。
- 打地鼠改以單調時鐘的截止時間計算剩餘秒數，重新開始時重設截止時間，避免 interval 相位吃掉新局時間。
- 所有延遲操作登記於目前遊戲 session，關閉、重玩或切換遊戲時一併取消。

## 3. 檔案與責任

| 路徑 | 責任 |
| --- | --- |
| `index.html` | 頁面骨架、十張遊戲卡、面板容器、無障礙地標 |
| `styles.css` | 色彩 token、卡片、遊戲控件、響應式與減少動態效果 |
| `app.js` | 大廳狀態、共用面板、十款遊戲控制器與分數持久化 |

| `tests/game-rules.test.mjs` | 純規則單元測試 |
| `.github/workflows/sdd-checks.yml` | Pull request 與 main 的 Node.js 檢查 |
| `specs/001-ten-in-one-arcade/*` | SDD 規格、研究、資料、契約、任務與 quickstart |

## 4. 風險與緩解

- Canvas 不提供繪製物件的語意資訊：旁邊提供文字狀態與按鈕，Canvas 僅負責視覺遊戲區。
- `localStorage` 可能因瀏覽器策略不可用：使用容錯包裝，絕不讓儲存失敗阻止遊戲。
- 計時器在切換遊戲時殘留：共用 runtime 以 `Set` 登記並在關閉、重玩或換遊戲時全部清理。
- 手機螢幕狹窄：以 CSS Grid、`minmax(0, 1fr)`、`clamp()` 與 720px 斷點重排，避免固定寬度。

## 5. 驗證策略

1. `node --check app.js`、`node --check src/rules.mjs` 與 `node --check scripts/verify.mjs` 確認語法。
2. `npm test` 執行純規則單元測試與靜態驗收，覆蓋方向反轉、蛇尾碰撞與統計資料正規化。
3. 啟動簡易靜態伺服器後執行 HTTP smoke test，並人工逐一點選十張卡，確認每款遊戲可開始、可重玩、可關閉；在窄視窗確認主要控件不溢出。
4. 由獨立小 AI 進行唯讀程式審查與測試；有可重現問題就修正並重跑，直到回覆「零問題」。
5. 以 GitHub Actions 在 PR 與 main 再跑一次相同檢查。
